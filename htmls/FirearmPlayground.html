    Extending the playground
    

    Everything lives in this one file. A firearm is three things: a JSON entry, a class and one line of registration. Search for class Revolver to see a complete example.
    

    1. Describe it in JSON (the #cfg script block)
    

    "breaker":{"name":"Break-action","cap":1,
  "steps":["Press the lever","Insert a shell","Close the action","Fire"]}
    

    • name: tab label. Key order sets tab order and the 1 to 9 hotkeys.
      • 

    • steps: the correct procedure, in order, shown in the side panel.
      • 

    • stub: optional. Set to 1 for a placeholder that has no logic yet. It also needs state, an object of initial state variables shown in the debug panel.
      • 

    • Any tuning number (capacity, round count) can live here. Read it in the class as this.c.cap.
    

    2. Write the class
    

    Extend Firearm. The constructor stores the JSON as this.c and calls reset(). Define the class above the const CLS line. Required members:
    

    • reset(): set this.s (every mechanical state variable: safety, action, chamber, magazine, hammer, slide or bolt position) and this.tray, the buttons under the stage, as [label,'action'] or [label,'action:7'] (the argument arrives as a number).
      • 

    • scen(): set a loaded, ready state for the challenge.
      • 

    • cleared(): true when the gun counts as safe: chamber and magazine, cylinder or tube empty, action open.
      • 

    • hint(): return the next correct step as text, based on the current state.
      • 

    • render(): return an SVG string with viewBox="0 0 800 330". Add class="xr" when G.xray is on.
      • 

    • do_name(arg): one handler per action. May be async.
    

    3. Handlers and the state machine
    

    • Check every precondition first. To block an invalid action, throw a plain-language string such as throw 'The action is open.'. It shows in red and costs 5 points.
      • 

    • Then change state and call snd(), say() and fx for feedback.
      • 

    • For a multi-phase move, set the first state, call draw();await wait(300);, then set the next state. wait stretches in slow-mo.
      • 

    • Input is locked while a handler runs, and draw() runs automatically afterwards.
    

    4. Draw the parts
    

    • P(action,label,description,svgInner) makes a clickable part with a tooltip and right-click description. An action of 'chamber:3' calls do_chamber(3).
      • 

    • R(class,x,y,w,h,extra) makes a rectangle. Classes: body (outline, turns translucent in X-ray), win (dark cutout), mag, brass (live round), spent (fired case), on (highlight for an engaged part).
      • 

    • Draw order is back to front. Put internals (rounds, hammer, bolt) before the shell parts that cover them.
    

    5. Effects and sound
    

    • fx.fire(x,y,{size}): muzzle flash, smoke, recoil and the gunshot sound. Pass the muzzle position. Use size 0.9 for a handgun, 1.7 for a shotgun.
      • 

    • fx.eject(x,y,'live'|'spent',{len,h,vx,vy,g,spin,delay,floor}): a case or round that arcs out, spins, lands with a clink and fades. Everything except the first three arguments is optional. Coordinates are SVG units (800 by 330, y points down).
      • 

    • snd(id) ids: click clack thunk metal load err tick ok.
    

    6. Register
    

    Add the class to the CLS map with the same key as the JSON entry: CLS={...,breaker:BreakAction}. To promote a stub, write its class, register it and remove "stub":1.
    

    7. Checklist before you ship a gun
    

    • Every state variable is in this.s (it appears in the debug panel).
      • 

    • Every impossible transition throws an explanation: closed action, absent or unseated magazine, full tube, firing with the safety on or the action open.
      • 

    • cleared(), scen() and hint() agree with each other. Test the challenge start to finish.
      • 

    • Every part has a label and a description. Every meaningful action has a sound, and ejection or firing uses fx.
      • 

    • The steps in JSON match the real correct order.
      • 

    • Try the full valid sequence, then each invalid action once, in both normal and slow-mo.
    

    Worked example: single-shot break-action
    

    class BreakAction extends Firearm{
 reset(){this.s={open:0,ch:null};this.tray=[['Insert shell','load']]}
 scen(){this.s={open:0,ch:'live'}}
 cleared(){return this.s.open&&!this.s.ch}
 hint(){const s=this.s;return s.ch?(s.open?'Take the shell out.':'Press the lever to open it.'):s.open?'Open and empty: clear.':'Press the lever.'}
 do_lever(){const s=this.s;s.open^=1;snd('clack');
  if(s.open&&s.ch==='spent'){fx.eject(330,150,'spent',{len:26,h:11});s.ch=null}
  say(s.open?'Action broken open.':'Action closed.')}
 do_load(){const s=this.s;if(!s.open)throw 'Break the action open first.';
  if(s.ch)throw 'The chamber is occupied.';s.ch='live';snd('load');say('Shell inserted.')}
 do_take(){const s=this.s;if(!s.open)throw 'The action is closed.';
  if(!s.ch)throw 'Nothing to remove.';s.ch=null;snd('load');say('Shell removed.')}
 do_trigger(){const s=this.s;if(s.open)throw 'The action is open.';
  if(s.ch==='live'){s.ch='spent';snd('click');fx.fire(700,140,{size:1.5});say('Primer struck: shell spent.')}
  else{snd('click');say('Click. Nothing to fire.')}}
 render(){const s=this.s;return '<svg viewBox="0 0 800 330" class="'+(G.xray?'xr':'')+'">'
  +R('body',200,120,360,24)
  +P('lever','Break lever','Opens the action',R(s.open?'on':'body',300,150,40,8))
  +P('trigger','Trigger','Releases the striker',R('body',320,170,10,30))
  +P('take','Chamber','Click to remove the shell',s.ch?R(s.ch==='live'?'brass':'spent',340,124,40,14):R('win',340,124,40,14))
  +'</svg>'}
}
const CLS={revolver:Revolver,pump:PumpShotgun,pistol:SemiAutoPistol,breaker:BreakAction};
